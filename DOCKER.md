# Docker deployment

Three hardened images, built from one static-Go Dockerfile:

| image target | binary | purpose |
| --- | --- | --- |
| `wan-ingress` | `cmd/wan-ingress` | WAN front: admit, resolve by agreement, sign and forward through the border |
| `seed-invite` | `cmd/seed-invite` | address plane: resolve isotope invites and require a signed rotational expectation |
| `seed-announce` | `cmd/seed-announce` | one-shot signer/publisher for DNS `TXT` or mDNS `TXT` rotations |

Each runtime stage is `gcr.io/distroless/static-debian12:nonroot`: one static
binary, no shell, no package manager, no writable root filesystem, UID 65532.
`cmd/healthcheck` is copied alongside the two long-running binaries so Docker
can probe `/healthz` without adding curl or wget.

## Quick start

1. Fill in the operator-owned placeholders:

   ```sh
   cp configs/docker/wan-ingress.json configs/docker/wan-ingress.local.json
   cp configs/docker/agreements.json configs/docker/agreements.local.json
   cp configs/docker/seed-invite.json configs/docker/seed-invite.local.json
   # edit token, border key, seed id, announcement key, DNS domain and border URL
   ```

   These files are **shapes**, not usable defaults. An empty token, key or seed
   leaves the stack fail-closed.

2. Point the compose mount at your local copies (or edit the mounted files in
   place), then start:

   ```sh
   SMOKE_ALARM_URL=http://smoke-alarm:19100 docker compose up -d --build
   ```

   `cp .env.example .env` gives you the full override set; `.env` is gitignored.

   `SMOKE_ALARM_URL` overrides the registry field in both configs through an
   explicit flag, so the same mounted file works in several environments. The
   real border and the smoke-alarm registry are operator-supplied services; the
   example agreements point at `http://border:9443/cluster`.

3. Check the stack:

   ```sh
   docker compose ps
   curl -fsS http://127.0.0.1:8443/healthz
   curl -fsS http://127.0.0.1:8080/healthz
   curl -fsS http://127.0.0.1:8080/status
   ```

Ports default to `8443` (ingress) and `8080` (address plane). Override with
`WAN_INGRESS_PORT` and `SEED_INVITE_PORT`.

## What "secured" means here

- **non-root** — all runtimes use UID/GID 65532.
- **no shell** — distroless static base; an attacker who gets a process cannot
  `sh`, `curl` or package-install their way sideways.
- **read-only rootfs** — only `/tmp` is a tmpfs; no config or binary is writable.
- **capabilities dropped** — `cap_drop: [ALL]`, `no-new-privileges: true`.
- **bounded** — `pids_limit: 64`, `mem_limit: 128m`, `cpus: 0.50`.
- **secrets outside the image** — tokens and HMAC keys live in mounted config
  files with `:ro`; no secret is baked into a layer. Use a secret manager or
  file-permission-controlled host mounts in production.
- **fail closed** — without agreements, token, border key and a live signed
  rotation, the ingress refuses or quarantines; the address plane returns `403`
  before resolution.

The shipped `wan-ingress` binary still knows nothing about DNS, mDNS or seed.
The boundary stays clean: seed/address plane narrows the visitor, agreement plus
HMAC border decides what may cross.

## Rotations

For production, publish the signed DNS `TXT` body generated by `seed-announce`
under the configured `dns_domain`. With the `announce` profile:

```sh
ANNOUNCE_KEY='<base64url key>' SEED_ID=seed-42 \
  ROTATION_ID=rot-1 NONCE=nonce-1 \
  docker compose --profile announce run --rm seed-announce
```

The printed `TXT` record can be pasted into the zone. mDNS is link-local, so it
only makes sense with host networking on a trusted LAN; it is not a WAN
transport. DNS is the production path.

## Builds

Local single-arch images are built by `docker compose build`. Multi-arch
`linux/amd64` + `linux/arm64` images come from the bake file:

```sh
docker buildx bake
# writes dist/wan-ingress.oci.tar, dist/seed-invite.oci.tar,
# dist/seed-announce.oci.tar (each contains linux/amd64 + linux/arm64)
```

OCI archives are used instead of `type=docker` because Docker's local image
store cannot load multi-platform images. Import one platform with
`docker image load --input dist/<name>.oci.tar` after export, or push from your
own registry pipeline. The same four Go binaries (`wan-ingress`, `seed-invite`,
`seed-announce`, `healthcheck`) are also emitted as static files by
`scripts/build-wan-ingress.sh` for non-container installs.

## Verify

```sh
docker compose config --quiet
docker buildx bake --print
./sheets/ingress/red_team_seed_invite.sh
go test ./... && go vet ./...
```

The red-team script attacks the address plane with poisoned DNS records, replay,
cross-name tickets, nonce floods and a lying peer. The feature file and isotope
identity are unchanged; the images carry no spec claim of their own.
